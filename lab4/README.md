### Анализ трафика утилиты ping

Будем выполнять команду, постепенно увеличивая размер пакета

```bash
ping -s <размер пакета> -c 10 kaaproject.github.io
```

Пойманные пакеты доступны в файле [ping.pcapng](./res/pcapng/ping.pcapng)

#### Структура пакетов

Утилита `ping` использует протокол ICMP. Протокол отправляет эхо-запрос и получает эхо-ответ, фиксируя время перемещения пакета туда и обратно. Разберем структуру пакетов

![Структура echo request](./res/img/Screenshot%202026-05-18%20at%2021.25.01.png)

- Ethernet II (Канальный уровень)
  - `Destination` - MAC-адрес шлюза по умолчанию
  - `Source` - MAC-адрес устройства
  - `Type` - поле типа протокола

- IPv4 (Сетевой уровень)
  - `Source` - ip источника
  - `Destination` - ip назначения
  - `Protocol` - протокол
  - `Version` - версия
  - `Header Length` - длина заголовка
  - `Header Checksum` - контрольная сумма заголовка
  - `Fragment offset` - смещение фрагмента
  - `Flags` - флаги
  - `Time to Live` - ограничение количества хопов
  - `Indetification` - идентификатор фрагмента

- ICMP (Сетевой уровень в OSI, поверх IP)
  - `Type` - код операции
  - `Checksum` - контрольная сумма
  - `Identifier` - уникальный id
  - `Sequence number` - порядковый номер запроса
  - `Data` - полезная нагрузка

#### Ответы на вопросы

1. **Имеет ли место фрагментация исходного пакета, какое поле на это указывает?**  
  Да, фрагментация имеет место, когда размер ICMP-пакета (заголовок + данные) вместе с IP-заголовком превышает Maximum Transmission Unit (MTU) сети. На это указывает поле `Flags` в IP-заголовке. Если установлен флаг More fragments, значит, этот пакет — не последний фрагмент. Также поле Fragment Offset будет ненулевым у всех фрагментов, кроме первого, указывая его положение в исходном потоке данных.

2. **Какая информация указывает, является ли фрагмент пакета последним или промежуточным?**  
  Если флаг More fragments установлен в 1, то после это промежуточный фрагмент, если флаг More fragments равен 0, то это последний фрагмент.

3. **Чему равно количество фрагментов при передаче ping-пакетов?**  
  Количество фрагментов равно размер пакета разделить на размер фрагмента

4. **Построить график зависимости количества фрагментов от размера пакета?**  
  ![Зависимость количества фрагментов от размера пакета](./res/img/num_of_fragments.png)

5. **Как изменить поле TTL с помощью утилиты ping?**  
  Команда для установки TTL, например, в 128:  

    ```bash
    ping -s 100 -m 128 -c 4 kaaproject.github.io
    ```

6. **Что содержится в поле данных ping-пакета?**
  В поле данных ping-пакета обычно содержится последовательность символов английского алфавита, которая циклично повторяется для заполнения заданного объема, а также timestamp

### Анализ трафика утилиты tracert (traceroute)

Запустим команду

```bash
sudo traceroute -I -n kaaproject.github.io
```

Пойманные пакеты доступны в файле [traceroute.pcapng](./res/pcapng/traceroute.pcapng)

Так как используется протокол ICMP из предыдущего этапа, разбирать его структуру еще раз не будем

#### Ответы на вопросы

1. **Сколько байт содержится в заголовке IP? Сколько байт содержится в
поле данных?**  
  Заголовок состоит из 20 байт. Полем данных для IP будет содержимое ICMP пакета, то есть 8 байт заголовок + поле данных ICMP пакета

2. **Как и почему изменяется поле TTL в следующих друг за другом ICMP-
пакетах tracert? Для ответа на этот вопрос нужно проследить изменение
TTL при передаче по маршруту, состоящему из более чем двух хопов**  
  Утилита отправляет серию пакетов с TTL, увеличивающимся на 1: сначала `TTL=1`, потом `TTL=2`, `TTL=3` и т.д.
  Это позволяет `traceroute` определить все узлы на пути

3. **Чем отличаются ICMP-пакеты, генерируемые утилитой tracert, от ICMP-
пакетов, генерируемых утилитой ping (см. предыдущее задание).**
  Пакеты в `ping` и `traceroute` будет отличаться по TTL (в `traceroute` это значение не фиксированное), также отличается поле данных, в `ping` оно фиксированное и заполняется в алфавитном порядке, в `traceroute` пустое или заполнено нулями

4. **Чем отличаются полученные пакеты «ICMP reply» от «ICMP error» и
зачем нужны оба этих типа ответов?**
  ICMP reply приходит от конечного узла, ICMP error от промежуточных. С точки зрения пакетов, у них отличается значение в поле Type в заголовке ICMP

5. **Что изменится в работе tracert, если убрать ключ «-d»? Какой
дополнительный трафик при этом будет генерироваться?**
  Утилита начнет для каждого полученного IP-адреса маршрутизатора выполнять обратный DNS-запрос, чтобы определить его доменное имя

### Анализ HTTP-трафика

При открытии страницы по варианту браузер отправляет HTTP-запрос к серверу. Если страница открывается по HTTPS, то без расшифровки TLS в Wireshark видны TCP- и TLS-пакеты, а не содержимое HTTP-заголовков.

#### Структура пакетов

- Ethernet II
  - `Destination` - MAC-адрес следующего узла
  - `Source` - MAC-адрес отправителя
  - `Type` - тип протокола верхнего уровня

- IPv4
  - `Source` - IP-адрес клиента
  - `Destination` - IP-адрес сервера
  - `Protocol` - TCP

- TCP
  - `Source Port` - временный порт клиента
  - `Destination Port` - порт сервера, обычно `80` для HTTP или `443` для HTTPS
  - `Seq/Ack` - номера последовательности и подтверждения
  - `Flags` - служебные флаги соединения

- HTTP
  - `Request Method` - метод запроса, например `GET`
  - `Host` - доменное имя сайта
  - `Status Code` - код ответа сервера
  - `Content-Type` - тип передаваемых данных

#### Ответы на вопросы

1. **Как HTTP передает содержимое страницы при первичном посещении?**  
  При первом обращении браузер отправляет обычный `GET`. Сервер возвращает ответ `200 OK`, HTTP-заголовки и тело страницы.

2. **Как HTTP передает содержимое страницы при повторном обновлении?**  
  При повторном запросе браузер может отправить `Conditional GET` с заголовками `If-Modified-Since` или `If-None-Match`. Если ресурс не изменился, сервер отвечает `304 Not Modified` без тела страницы, и браузер берет данные из кэша. Если ресурс изменился, сервер снова возвращает `200 OK` и новое тело ответа.

### Анализ DNS-трафика

Перед обращением к сайту браузеру нужно получить IP-адрес доменного имени `kaaproject.github.io`. Для этого генерируются DNS-запросы.

#### Структура пакетов

- Ethernet II - передача кадра до следующего узла
- IPv4 - доставка пакета до DNS-сервера
- UDP - транспортный протокол DNS, обычно порт `53`
- DNS
  - `Transaction ID` - идентификатор запроса
  - `Queries` - запрашиваемое имя и тип записи
  - `Answers` - найденные DNS-записи
  - `TTL` - время кэширования ответа

#### Ответы на вопросы

1. **Почему адрес, на который отправлен DNS-запрос, не совпадает с адресом посещаемого сайта?**  
  DNS-запрос отправляется не на сервер сайта, а на DNS-резолвер: роутер, DNS-сервер провайдера или публичный DNS. Уже этот сервер возвращает IP-адрес нужного домена.

2. **Какие бывают типы DNS-запросов?**  
  Основные типы: `A` для IPv4-адреса, `AAAA` для IPv6-адреса, `CNAME` для псевдонима, `NS` для DNS-серверов зоны, `MX` для почтовых серверов, `TXT`, `SOA`, `PTR`, `SRV`.

3. **В какой ситуации нужно выполнять независимые DNS-запросы для получения содержащихся на сайте изображений?**  
  Если изображения загружаются с другого домена или поддомена, например CDN. Тогда браузер отдельно разрешает имя этого хоста в IP-адрес.

### Анализ ARP-трафика

ARP используется, чтобы определить MAC-адрес узла в локальной сети по его IP-адресу. При обращении к внешнему сайту компьютер обычно ищет не MAC-адрес сервера сайта, а MAC-адрес шлюза по умолчанию.

#### Структура пакетов

- Ethernet II
  - `Destination` - широковещательный адрес `ff:ff:ff:ff:ff:ff` для запроса или MAC получателя для ответа
  - `Source` - MAC-адрес отправителя
  - `Type` - ARP

- ARP
  - `Sender MAC address` - MAC-адрес отправителя
  - `Sender IP address` - IP-адрес отправителя
  - `Target MAC address` - искомый MAC-адрес
  - `Target IP address` - IP-адрес, для которого ищется MAC

#### Ответы на вопросы

1. **Какие MAC-адреса присутствуют в ARP-пакетах? Что они означают?**  
  В ARP-запросе присутствует MAC-адрес компьютера и широковещательный адрес `ff:ff:ff:ff:ff:ff`. В ARP-ответе появляется MAC-адрес шлюза или другого локального узла, которому принадлежит запрошенный IP.

2. **Какие MAC-адреса присутствуют в HTTP-пакетах и что они означают?**  
  В Ethernet-заголовке HTTP-пакета указаны MAC-адрес компьютера и MAC-адрес следующего узла, обычно шлюза. MAC-адрес удаленного веб-сервера в локальном кадре не передается, потому что он находится за пределами локальной сети.

3. **Для чего ARP-запрос содержит IP-адрес источника?**  
  Чтобы получатель знал, кому отправлять ARP-ответ, и мог при необходимости обновить свою ARP-таблицу.

### Анализ трафика утилиты nslookup

Запустим команды

```bash
nslookup kaaproject.github.io
nslookup -type=NS kaaproject.github.io
```

#### Ответы на вопросы

1. **Чем различается трасса трафика в двух командах?**  
  В первом случае выполняется запрос адресных записей `A` и/или `AAAA`, чтобы получить IP-адрес сайта. Во втором случае выполняется запрос `NS`, чтобы получить список DNS-серверов, обслуживающих доменную зону.

2. **Что содержится в поле `Answers` DNS-ответа?**  
  В поле `Answers` находятся ресурсные записи DNS: имя, тип записи, класс, `TTL` и значение записи. Для `A` это IPv4-адрес, для `AAAA` IPv6-адрес, для `NS` имя DNS-сервера.

3. **Каковы имена серверов, возвращающих авторитативный отклик?**  
  Для зоны `github.io` в ответе `NS` возвращаются серверы `dns1.p05.nsone.net`, `dns2.p05.nsone.net`, `dns3.p05.nsone.net`, `dns4.p05.nsone.net`, `ns-393.awsdns-49.com`, `ns-692.awsdns-22.net`, `ns-1339.awsdns-39.org`, `ns-1622.awsdns-10.co.uk`.

### Анализ FTP-трафика

FTP использует отдельное управляющее соединение и соединение для передачи данных. Для анализа в Wireshark удобно использовать фильтр:

```bash
ftp || ftp-data
```

#### Структура пакетов

- Ethernet II - передача кадра по локальной сети
- IPv4 - доставка пакета между клиентом и FTP-сервером
- TCP - надежное соединение
- FTP - команды и ответы сервера
- FTP-DATA - содержимое передаваемого файла

#### Ответы на вопросы

1. **Сколько байт данных содержится в пакете FTP-DATA?**  
  Количество байт видно в поле `TCP payload` или `FTP-DATA`. Обычно один полный сегмент содержит до размера MSS, например около 1460 байт, а последний сегмент может быть меньше.

2. **Как выбирается порт транспортного уровня для передачи FTP-пакетов?**  
  Управляющее соединение использует TCP-порт `21`. Для передачи данных в активном режиме сервер обычно использует порт `20`, а в пассивном режиме сервер сообщает клиенту временный порт, к которому клиент подключается сам.

3. **Чем отличаются пакеты FTP от FTP-DATA?**  
  `FTP` содержит команды и ответы, например `USER`, `PASS`, `RETR`, коды `220`, `230`, `226`. `FTP-DATA` содержит непосредственно байты передаваемого файла.

### Анализ DHCP-трафика

Для анализа DHCP используется фильтр `bootp`, потому что в Wireshark DHCP отображается как расширение протокола BOOTP.

```bash
ipconfig /release
ipconfig /renew
```

#### Последовательность обмена

```text
Клиент -> Broadcast: DHCP Discover, UDP 68 -> 67
Сервер -> Клиент/Broadcast: DHCP Offer, UDP 67 -> 68
Клиент -> Broadcast: DHCP Request, UDP 68 -> 67
Сервер -> Клиент/Broadcast: DHCP ACK, UDP 67 -> 68
```

#### Ответы на вопросы

1. **Чем различаются пакеты `DHCP Discover` и `DHCP Request`?**  
  `Discover` используется для поиска доступных DHCP-серверов. `Request` отправляется после получения предложения и подтверждает выбор конкретного сервера и запрошенного IP-адреса.

2. **Как и почему менялись MAC- и IP-адреса источника и назначения?**  
  До получения адреса клиент использует IP `0.0.0.0` и широковещательный адрес назначения `255.255.255.255`. На канальном уровне запросы отправляются на `ff:ff:ff:ff:ff:ff`. После выдачи адреса клиент начинает использовать назначенный IP.

3. **Каков IP-адрес DHCP-сервера?**  
  IP-адрес DHCP-сервера указан в поле `Server Identifier`, а также может совпадать с IP-адресом источника в пакетах `Offer` и `ACK`.

4. **Что произойдет, если очистить использованный фильтр `bootp`?**  
  В списке пакетов появится весь остальной сетевой трафик: ARP, DNS, TCP, HTTP/HTTPS и служебные пакеты других приложений.
